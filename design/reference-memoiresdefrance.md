## 一、四个点：他们怎么做，我们拿什么

### 1. 视觉设计（只能看到结构）

**他们：** 标题层级很干净：H1 页面名，H2 大段，H3 条目名，H4 条目里的小节；没有多余装饰。
标题上方有一行小标签说明“这是什么”（例如“公共措施 · 部分覆盖”）；标题下面一段导语；再下一行写“几条相关内容 · 某日更新”。
段落标题后面带数字，例如“演变和组成部分（2）”。每页开头有面包屑（首页 › 措施 › 某某）。页脚有一句固定的提醒。

**我们拿：**
- 标题上方的“这是什么”一行：我们条目页已有（“Item 1042 · Promise · Transport”），人物页和主题页也照这样加一行。
- 段落标题带数字：“Items (14)”“Evidence (2)”。读者先知道下面有多少再决定看不看。
- “某日更新”这一行：用 `confirmed_at` 的最新日期，放在页头，告诉读者这页的数据截至哪天。

**不拿：** 首页上的大菜单、“即将推出”的预告、竞选年份的醒目入口。我们两个字号、两个字重的规矩不变。

### 2. 思路怎么组织

**他们：** 先把规则公开，再给结果。总览页先列一份带版本号和发布日期的“分类表”，每种状态都有三块：定义、
触发它的文件类型（法律、预算）、边界情况。每页都写覆盖范围（“不是完整历史”“100% 至少有一个来源”），
把“记录的事实”和“编辑的分析”分开说，页脚有更正（答辩权）入口。

**我们拿：**
- **方法页每种结论加“边界情况”**，用难例写，例如（虚构）“承诺每户都能接入光纤，期限到时覆盖 90.5%”
  为什么是“部分成真”而不是“成真”。读者和评审团用的是同一份尺子。
- **方法写版本号和日期。** 条目页“怎么判的”一栏写“按方法第几版判定”。记录格式里没有这个字段（只有
  `jury_votes.prompt_version`），需要的话由总协调另提，我不改 schema。
- **覆盖范围一句话**：人物页写“这里收录了 N 份文件里的 M 条，不是此人说过的全部”。数据可以自动算出来。

**不拿：** 他们把“分析未完全核实”的条目也公开了，我们不公开未经确认的结论。他们给每条承诺分“结构性 / 重大 / 显著”
三档影响力，这是编辑给的权重，等于排序，和原则 3 冲突。他们的状态名（例如 tenue / non tenue，“守住 / 没守住”）
带有守诺与否的意味；我们继续只描述结果（成真 / 未成真）。

### 3. 人物页（他喜欢的“干净”）

**他们，从上到下：** 面包屑；头像、姓名、任期、党派、政治立场；任期数和分析条目数；
一段话说明计数是按规则机械算出的、不是评价；**全部任期的百分比总分**；然后按每次选举分块，每块有得票率、
一段说明、这次选举的百分比、来源覆盖率、条目列表；状态和领域两个筛选器；每条可以在页面里展开，
看分析和来源；条目链接到相关的措施页。

我的看法：它“干净”主要是因为**单栏、一条线读下去**，而且**按选举分块**，读者有时间感。但它第一块内容是百分比总分，
各块里又是百分比，这恰恰是我们定了不做的。

**我们拿：**
- **按“在哪说的”分块。** 条目按来源文件和身份分组（例如“2020 市政选举纲领 · 市长候选人 · 12 条”），组按日期排列，
  每组标题下面写六种结论的计数。这就是我们要的编年感。数据已有（`claims.source_id`、`speaker_role_{lang}`、`said_on`），
  不用改格式。现在默认按领域分组，改成领域作为筛选。
- **条目行带上结论说明。** 他们每张卡片展开后结论和分析、来源在一起。我们的做法更简单：行里结论标签下面直接显示
  `summary_{lang}`（最多两行），整行仍然链到条目页。这样人物页上每个结论都带着依据，不只是靠链接。
- **计数下面一句话**：“这些是计数，不是评分。”平静，说一次就够。

**不拿：** 头像、党派、左中右立场标签、得票率、百分比、总分、来源覆盖率百分比、在页面里展开整条记录
（我们有条目页，展开会让人物页变成长卷）。

### 4. 专题页怎么排信息

**他们，从上到下：** “这是什么 · 覆盖程度”一行；标题；一段导语（它是什么，**它不是什么**）；“几条内容 · 某日更新”；
**“覆盖范围、边界和来源”放在正文第一块**；然后是**带编号的时间顺序列表**，每项有日期、类型、核实状态、标题、
一句摘要、当时的总统和政府、链接；最后是“其他提到它的内容”，链回人物页里的那条承诺。

**我们拿：**
- **条目页的“依据”改成一条按日期排的时间线**（这是本提议里我最推荐的一条）。现在的“Based on”列表、截止日期、
  确认日期是三块；按时间排成一列就是：说出的日子（来源）→ 各份凭据的发布日期 → 截止日期（写明谁定的）→
  人工确认的日子。内容一字不加，只换了顺序，读起来就是一段编年史，结论的依据仍然在同一屏。
- **“用同一份文件核对的其他条目”。** 他们靠“其他提到它的内容”把专题和承诺连起来。我们可以不建专题表，
  直接用 `verdict_evidence` 找出引用同一份凭据的其他条目，列在条目页详细层。全自动（原则 7），不需要人去挑。
- **真正的专题页（一项政策或一件事，把所有人说过的话和官方文件按时间排在一起）** 价值很高，但记录格式里没有
  “这条属于哪个专题”的字段。需要的话由总协调提出格式改动；MVP 不做。

**不拿：** “内容未核实”的标记（我们不发布未核实的）；当时的总统和政府那一栏（我们只写说话人的身份）。

## 二、明确不学的（和我们的原则冲突）

| 他们的做法 | 为什么不学 |
| --- | --- |
| 百分比、“总分”、每位总统的“兑现率”卡片 | DESIGN.md 规则 8：只给计数，不给比例；并排的比例就是排名（原则 3） |
| 头像、党派、政治立场标签 | 规则：无肖像、无党派色；立场标签是编辑判断（原则 3） |
| 影响力分档（结构性 / 重大 / 显著） | 编辑给的权重，等于给条目排序（原则 3） |
| 公开“分析未完全核实”的条目 | 我们不发布未确认的结论（CLAUDE.md） |
| 来源只列链接和类型代码 | 我们每份来源有标题、出版者、位置、日期、取回日期、指纹（原则 2） |
| 长段分析（4 到 8 句） | 摘要层要短，一次点开不超过一屏 |
| 得票率、选举背景数字 | 和核对无关，而且不在我们的记录里，无源不录（原则 2） |
| 大菜单、“即将推出”预告 | 极简；不预告没做的东西 |

### 待定问题：第六种结论用什么图案

现在五种：无法验证 = 横线，待定 = 空白，待评估 = 点，成真 = “/”，未成真 = “\”（镜像）。“部分成真”要排在“成真”和
“未成真”之间，三种的分量要相同。

- **A（推荐）竖线“|”。** 正好是“/”和“\”的对称轴，三者同样密度、同样墨量，读起来“/ | \”是一组；不暗示好坏。
  风险：和“无法验证”的横线只差方向，8 px 小块上要实测能不能分清。
- B 稀疏的“/”（间距加倍）。意思直观（成真的一部分），但更浅，看起来“分量更轻”，违反同等分量。
- C 交叉线“×”。墨量是其他的两倍，图上最显眼，违反同等分量。

建议选 A，开稿前在 375 px 手机上做环形图和条形图的实测；分不清就把“无法验证”的横线改成更稀的横线。

## 依据哪条原则

- 原则 3：不学百分比、总分、影响力分档、立场标签；“成真”“部分成真”“未成真”图案同等分量。
- 原则 2：条目页依据排成时间线，列表行带说明，结论始终和依据同屏。
- 原则 1：覆盖范围写明“没收录什么”；“待评估”的“还缺什么”位置不变。
- 原则 5：第 2、3 条不加新部件，只重排已有内容；专题页和面包屑放后面或不做。
- 原则 7：“同一文件的其他条目”和覆盖范围计数都由数据自动得出，不人工挑。

## 异议与风险

- **这个网站最显眼的东西正是我们不做的。** 总览页和人物页的第一块内容都是百分比总分。创始人喜欢的“简单”，
  我判断来自单栏顺读和按选举分块，而不是总分。如果他喜欢的恰恰是那个总分一眼看清的感觉，我们需要单独谈：
  我会反对，理由是规则 8 和原则 3。
- **视觉部分没看到真实页面**，第 1 点是推断。没有截图之前，不要把这份当成视觉方向的结论。
- 第 3 条让行变长，手机上一屏看到的条目更少；如果实测太长，退一步只在人物页显示说明，首页卡片不显示。
- 第 4 条按来源文件分块：同一人在很多场合零散说的话会变成很多小块。超过一定块数时（建议 8）退回按年份分块。
- “部分成真”的竖线图案要实测，可能和横线混淆。
- 第 6 条的“方法版本”和第 10 条的专题都需要记录格式字段，我没有改 `db/schema.sql`，只在这里提出。

## 做了什么

**前 5 项（总协调批准）：**

   我没有浏览器可以实际渲染，**这是推演，不是实测**。条目页加了“部分成真”变体，用虚构人物和虚构数字

   `oq_fr/oq_en`（只限待评估）、`src`、`ev`、`sources`，全部来自现有快照，不改记录格式（`ia.md` 第 2 节）。

5. 人物页加“结论截至某日”、覆盖范围一句、“这些是计数，不是评分”。

**创始人截图里的做法（总协调要求两种配色都带上）：**

- 列表行做成白色圆角卡片，**就地展开**：完整说明、依据文件和类型、截止日、确认日、完整记录链接。
  用原生 `<details>`，不开 JavaScript 也能用。这正是创始人说的“摘要层 / 详细层”。

- 来源文件分块的标题用衬线（它是对方文件的标题，属于“他们的话”）。
- **配色 A/B**：A 是现行规范（一种墨色加花纹）；B 每种结论一个亮度相近的柔和色，没有红绿，花纹保留。
  **创始人选定 B**，现在是唯一配色；A/B 切换和对比页已撤掉（对比度计算见 `tokens.md`）。

**没做的：** 面包屑（价值低，条目标题已经链到人物）；日期和编号用等宽字体（多一种字体用法，没有必要）；
专题页和方法版本号（要改记录格式，留到以后，见 `ia.md` 风险第 6 条）。

## 依据哪条原则

## 异议与风险

- **配色：创始人选了 B，我的异议保留。** 六种颜色可能被读成一把好坏尺子（“蓝的就是好的”）。
  缓解：不用红绿，六色亮度相近，花纹和文字标签始终都在，只给计数。读者或中立性审查发现颜色被当成分数时再议。
- **图标：我没有照总协调列的 ✓ / × / ⚠ 去做。** 冻结的规范明写不用打勾和打叉，而且勾和叉就是褒贬。
  用花纹做图标，同样有“一眼看出”的效果。创始人要勾叉的话，需要他改规范。
- 两行说明会被截断：说明必须先写结果和数字。建议在评审团提示词里加一句（不是我的文件）。
- 手机上一屏能看到的条目变少（卡片留白加说明行）。
- 系统衬线体比对方网站的展示字体朴素，不加载网络字体就只能这样。
- 我没有实际渲染过任何页面（这次会话没有浏览器工具）。CSS 和脚本是按代码逐行检查的，需要有人在
  375 / 1024 / 1440 px 和深色模式下看一遍，再跑一次 accessibility-review。
