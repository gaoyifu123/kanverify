# 审核台（本机）设计规范

- 角色：设计。日期：2026-11-22。状态：初稿，等总协调和创始人看过后再交开发。
  同日按总协调的改动修订：无标记的候选自动收录，队列 A 只放带标记的；队列 B 加“驳回条目”。
- 视觉稿：`design/mockups/desk.html`（虚构数据；两个队列和主要状态都在一页里，从上往下看）。
- 依据：`PRINCIPLES.md`（尤其原则 7）、`design/DESIGN.md`、`tokens.md`、决策 0005、0008、0010、
  `src/pack.js`、`src/ledger.js`、`db/schema.sql`。

## 1. 它是什么，不是什么

只在创始人自己电脑上运行的一个本地页面（只监听 `127.0.0.1`），做两件机器做不了的事：

| 队列 | 页面回答的问题 | 每条目标用时 |
| --- | --- | --- |
| A 候选（只有带标记的） | “复查标出的这个疑点怎么处理？” | 简单的一条 10 秒以内 |
| B 结论（每一条都经过） | “这是一条该收录的承诺或预测吗？它的结论和凭据能不能用我的名义公开？” | 不设目标，只记录（见 §6） |

**自动收录（总协调 2026-11-22 改动，原则 7）。** 原话核对通过（`verbatim: true` 且页码一致）、
复查没有任何标记、字段能通过数据库规则的候选，由程序直接写进工作区 `claims`，不经过审核台，
审核记录里记一行 `auto_accept`。今天约 444 条里约 90 条带标记，只有这些进队列 A。
其余的不是没人看：每一条在结论队列 B 里都会到创始人面前，他在那里看到原话，也可以驳回条目本身（§5.3 `X`）。
所以“收录”是进工作区，“公开”永远要 B 里的确认。

进队列 A 的条件（任一）：复查 `status` 是 `duplicate` 或 `possible_duplicate`；有 `not_a_promise` 或
`continuation` 标记；有 `proposed_fixes`；`needs_founder: true`；原话核对没通过；字段过不了数据库规则
（如可量化却没有判定标准）；来源没关联说话人。只有 `consistency_note`（仅供参考）的不进队列。

它不是网站，不对外；界面用中文，原话和凭据保留原语言（加 `lang`）。不做搜索、筛选、统计图、多人协作。

## 2. 视觉

沿用网站的一套：`kanverify.css` 的变量、调色板 B、结论标签（`.verdict`，图案 + 色调 + 文字）、
`.quote`（衬线，他们的原话）、`.translation`、`.meta`。两种字号、两种字重，不加新的。
笔记本屏幕（1366 × 768 起）：宽于 1024 px 时两栏；窄了就一栏，照样能用。浅色和深色跟随系统。

审核台独有的只有：键帽 `kbd`、底部固定的操作栏、顶部一行的提示条（toast）、发布警示框（2 px 墨色边框，
不用红色）。“未成真”和“成真”在这里也同样的样式，不加任何警示色（原则 3）。

## 3. 顶部一行（两个队列共用）

`KANVERIFY 审核台 | 候选 · 剩 N | 结论 · 剩 N | 今天：自动收录 k · 接受 a · 拒绝 r · 确认发布 c · 驳回 x · 人工用时 m 分（候选平均 x 秒，结论平均 y 秒）`

“自动收录”放在最前，让创始人每天看得到有多少条没经过他就进了工作区。

- “今天”按本机日期，0 点归零。数字来源见 §7。
- 只有计数，没有进度条、没有目标线、没有“连击”之类。

## 4. 队列 A：候选

### 4.1 一屏的内容（从上到下，就是阅读顺序）

左栏：
1. **复查标记**（来自 `review-*.json` 的 `flags`、`status`、`proposed_fixes`），只在有的时候出现：
   - 重复 / 可能重复：写出另一条的编号、页码和原话，让人不用翻就能比；
   - 不是承诺（high / low）：写出理由原文；
   - “继续 / poursuivre” 类：写出“需要基线”；
   - 建议修正：`字段 旧值 → 新值` + 理由原文 + “按 F 采纳并接受”；`needs_founder: true` 的修正同样显示，不预先采纳。
   - 一致性说明：一行，灰字（单独有它不进队列，和别的标记同时出现时才显示）。
2. **原话**（衬线，原语言）+ 页码 / § + 程序核对结果（“逐字一致（第 9 页）”或核对失败，见 4.4）。
3. **译文**（另一种语言；原话是英文时显示法文，原话是第三种语言时两种都显示）。
4. **字段**：说话人和职务、类型、领域、可验证性、期限和依据（写明 / 推断）、判定标准 FR、判定标准 EN。
   代码一律显示中文名（见 §9），不显示 `foreign_affairs` 这类代码。

右栏：**原件那一页**（PDF 用存档的转写 `source-<id>-text.json`；网页用段落；法规用条文），
候选原话用 `<mark>` 标出并自动滚到它；空格键滚动右栏；`O` 用系统程序打开本机存档原件。

标题行：`候选 n / N`（本来源内的位置）+ 来源名 + 全部剩余数 + 本条计时。

### 4.2 顺序

按来源，再按候选在来源里的顺序（`index`）。同一页的候选连着出现，右栏不用换页，最快。
跳过的排到全部队列最后。

### 4.3 操作和快捷键

| 键 | 操作 | 写什么 |
| --- | --- | --- |
| `A` | 接受 | 在工作区 `claims` 插入一行（字段对照见 4.5）；审核记录追加一行 `accept` |
| `F` | 采纳建议修正并接受（只在有建议时可用） | 同上，字段先按建议改；审核记录写明采纳了哪几条 |
| `E` | 编辑后接受 | 打开字段表单：`Tab` 走字段，`Ctrl+Enter` 保存并接受，`Esc` 放弃。保存时程序重新核对原话（4.4）和数据库规则（可量化必须有判定标准；有期限必须有依据）；不过就停在表单里，写明哪个字段为什么 |
| `R` | 拒绝 | 弹出理由面板：`1` 重复（有重复标记时预选，并带上另一条的编号）`2` 不是承诺或预测 `3` 原话不对 `4` 其他（必须写一句）；`Enter` 完成，`Esc` 取消。不写数据库，审核记录追加一行 `reject` |
| `S` | 跳过 | 审核记录追加一行 `skip`；这一条排到最后 |
| `Z` | 撤销上一步，可以连按往回走（只限本次打开页面以后的操作） | 接受的：删掉刚插入的那行 `claims`（只在它之后没被改过、没有结论时；否则提示“这一条已经有后续改动，去工作区改”）；拒绝和跳过：追加一行 `undo`，指向被撤销的那一行。回到那一条 |
| `Q` | 切到结论队列 | — |
| `?` | 快捷键一览 | — |

每次操作后立刻显示下一条，顶部提示条写“已接受 s4-26 → 工作区条目 #212。Z 撤销”，留到下一次操作。
按钮和键等价；键只在焦点不在输入框里时生效。

### 4.4 不能接受的情况（`A` 和 `F` 停用，按钮虚线，原因写在原话下方）

- 程序在原件里找不到逐字一致的原话（`verbatim: false`），或找到的页和候选写的页不一致。
  只能 `E` 改正后重核，或 `R` 拒绝（理由 3）。
- 原件或转写缺失、哈希不符（`sourceUnits` 返回 `error`）：右栏显示错误原文，整条只能 `S` 跳过。
- 可量化但没有判定标准：只能 `E`。
- 这份来源还没关联说话人（见 4.5）：整份来源的候选都停用，顶部写明。

### 4.5 接受时写入 `claims` 的字段

`subject_id`（来源对应的人物，见“异议与风险”第 1 条）、`speaker_role_fr/en`、`type`、`domain`、
`quote_original`、`lang`、`quote_fr`、`quote_en`、`said_on` = 来源的 `published_on`、`source_id`、
`source_locator` = 候选的 `locator`、`verifiability`、`deadline`、`deadline_basis`、`criteria_fr`、`criteria_en`。
插入人物时不指定 `id`（决策 0005）。

### 4.6 10 秒怎么做到

没有标记的已经自动收录，队列里每条都有一个疑点，所以疑点放在最上面，后面紧跟能回答它的东西：
可能重复的，另一条原话就写在标记里；建议修正的，`F` 一键采纳。简单的一条：读标记、读原话，按 `F`、`A` 或 `R 1 Enter`。
不需要确认框；错了按 `Z`。

## 5. 队列 B：结论

### 5.1 一屏的内容

1. **发布警示**（一直在，不可关闭）：
   “确认 = 公开发布。写入账本后不能修改或删除，只能撤回，而撤回本身也公开。按 C 后有 5 秒，期间按 Z 可以取消，什么都不会写入。”
2. **条目**：说话人、职务、出处（标题、日期、位置）、原话、译文、类型、领域、可验证性、期限和依据、判定标准 FR/EN。
   标题行写明它是怎么进工作区的：“自动收录”或“候选队列接受”。自动收录的条目这是创始人第一次看到它，
   所以条目下面有一行折叠的“原件这一段（P）”：存档原文里原话所在的段落，原话用 `<mark>` 标出，和队列 A 右栏同一个组件。
   再次确认的条目在标题行写“有未确认的改动”（`hasUnconfirmedChanges`），并列出和上一次账本快照不同的字段。
3. **凭据包**（左栏）：摘录按 `[1]…[n]` 编号，每段写来源种类（中文名）、标题（衬线）、发布方、日期、位置，再是摘录原文。
   下面折叠一行“看过未用：k 段（U）”和“缺口”（`considered_not_used`、`gaps`，决策 0010 要求抽查时看得到）。
   剪辑者和模型一行灰字。
4. **评审票**（右栏，并排，每位一列）：编号 `1/2/3`、模型（等宽）、渠道（订阅 / API）、结论标签、
   引用了哪几段（点击跳到左栏那一段）、法语说明、英语说明（灰字）、折叠的“理由（工作笔记，不公开）”。
   没通过程序检查的票（`checkVote` 有问题）照样显示，但标“这一票没通过程序检查：…”，不计入一致数。
5. **一致标记**：`3 : 0 一致` / `2 : 1 分歧` / `1 : 1 : 1 分歧`，后面一句白话说明。一致与否用文字，不用颜色。
6. **将要发布的内容**：结论标签 + 采用的是哪一票 + 凭据编号 + 说明 FR/EN + 发布检查结果
   （`publicationBlockers` 为空时写“全部通过”，否则逐条列出，见 5.4）。结论和凭据在同一屏，原则 2。

### 5.2 顺序

一致且检查通过的在前，分歧的其次，检查没通过的最后；同组内按条目编号。理由：最快的先清掉，
需要想的集中在一起。

### 5.3 操作和快捷键

| 键 | 操作 | 写什么 |
| --- | --- | --- |
| `C` | 确认并发布 | 先进入 5 秒等待（下一条已显示，顶部提示“条目 #87 将在 4 秒后写入账本。Z 取消”）；到时调用 `confirm(db, claimId, 'founder', { reviewSeconds })`，提示改为“已写入账本，记录 #1043（用时 81 秒）”。检查没通过时停用 |
| `1` `2` `3` | 采用第 n 票 | 工作区 `verdicts` 这一行改为该票的结论、说明 FR/EN、待评估时的“还缺什么” FR/EN，`decided_by = 'jury'`；`verdict_evidence` 换成该票引用的摘录（原文和位置取自凭据包）。默认采用多数票；三票各不相同时不预选，`C` 停用直到选一票 |
| `E` | 编辑说明 | 表单：说明 FR、说明 EN；结论是“待评估”时加“还缺什么” FR/EN；另有结论下拉（六种，固定顺序）。`Ctrl+Enter` 保存到工作区 `verdicts`，`Esc` 放弃。只改文字时 `decided_by` 不变；改了结论时设为 `'human'`。保存后重新跑发布检查 |
| `B` | 退回 | 面板：退给谁 `1` 剪凭据包 `2` 重新评审 `3` 条目本身 `4` 翻译；一句说明（必填）。不写数据库，审核记录追加 `send_back`；条目离开队列，直到它的凭据包或评审票变了 |
| `X` | 驳回条目（这条本不该收录） | 面板：`1` 不是承诺或预测 `2` 抽取有误（原话截错、页码错、拆错或合错）`3` 与另一条重复（填编号）`4` 其他（必须写一句）；`Enter` 完成。审核记录追加一行 `reject_claim`，**连同这条的完整工作区内容（`claims`、`verdicts`、`verdict_evidence`、`jury_votes` 各行）**，然后从工作区删掉这条（连带删除它的结论、凭据、投票，决策 0005 允许工作区删除）。只对从没公开过的条目可用；已公开的停用，提示“已公开的只能撤回”，撤回不在审核台做 |
| `S` | 跳过 | 审核记录追加 `skip`；排到最后 |
| `Z` | 撤销 | 驳回：按审核记录里存的内容把这条放回工作区（新编号），追加 `undo`。5 秒内：取消待写入的确认（不写任何东西）。5 秒后：确认撤销不了，提示“已写入账本，只能在工作区撤回”。对采用、编辑：恢复改动前的 `verdicts` 行 |
| `U` | 展开 / 收起“看过未用” | — |
| `P` | 展开 / 收起“原件这一段” | — |
| `Q` / `?` | 切到候选队列 / 快捷键一览 | — |

**驳回（`X`）和退回（`B`）的区别：** 退回是“这条该收录，但凭据、判定或翻译要重做”；驳回是“这句话本来就不该进来”。
驳回的理由同时也是对自动收录的检验：审核记录里 `reject_claim` 中来自 `auto_accept` 的比例，就是复查标记漏掉的比例（见异议 10）。

**为什么确认用 `C` 而不是 `A`：** 候选队列里按了几百次 `A`，手会记住；“发布”换一个键，手不会顺带按下去。

**为什么要 5 秒等待而不是确认框：** 确认框按几百次以后会被不看就按掉；等待不打断节奏，又给一次反悔的机会。
页面在 5 秒内被关掉，那一条就不写入（安全的方向）。

### 5.4 不能确认的情况

`publicationBlockers` 返回的原因按它的顺序逐条列出，中文转写如下（开发按这张表翻）：

| 检查 | 审核台显示 |
| --- | --- |
| has_subject | 条目指向的人物不存在 |
| origin_is_own_words | 出处缺失，或不是本人公开说的话 |
| has_verdict | 还没有结论 |
| verdict_fits_verifiability | 含糊或有保留的条目只能是“无法验证” |
| summary_stated | 除“待定”外，结论要有说明 |
| outcome_has_evidence | 这个结论需要一份官方文件，或两家不同发布方的独立报道（本人公开放弃只能用于承诺的“未成真”） |
| evidence_is_primary | 凭据里有讲话、纲领、放弃声明或缺失的来源；凭据必须是官方文件或独立报道 |
| bilingual | 缺法语或英语译文：写明是哪一段（原话、第几段摘录、职务、标准、说明、还缺什么） |

审核台里能修的只有说明和结论（`E`、`1–3`）；其余的只能 `B` 退回或 `S` 跳过。
凭据包本身没通过 `checkPack`：整条停用，列出问题原文，只能退回（理由 1）。

## 6. 计时（原则 7）

- 每条从显示开始计，到操作完成为止；页面不在前台或 120 秒没有键盘鼠标动作时暂停（不把午饭算进去）。
- 结论队列：秒数随 `confirm()` 写进 `publications.review_seconds`；退回和跳过的秒数写进审核记录。
- 候选队列：秒数写进审核记录。
- **只在候选队列显示本条计时。** 结论队列照样记录但不显示：看着秒表审结论，会催人不读就按。

## 7. 审核记录（新增的一个文件，不是新表）

候选的拒绝、跳过、退回在数据库里没有地方放（原则 5：现有的不够，所以要加东西）。最小的做法是一个只追加的文本文件
`data/desk/actions.jsonl`，一行一个动作：

`{"at":"2026-11-22T10:31:07+01:00","by":"founder|program","queue":"candidate","item":"s4-27","action":"auto_accept|accept|accept_with_fixes|reject|skip|send_back|reject_claim|confirm|undo","reason":1,"note":null,"claim_id":212,"publication_id":null,"fixes":["domain"],"edited":["criteria_en"],"seconds":7,"undoes":null,"removed":null}`

- `auto_accept` 由收录程序写（`by: "program"`，`seconds` 为空）；`reject_claim` 的 `removed` 存被删的工作区各行，供撤销和日后查看。
- 候选队列靠它知道哪些已处理（最后一个未被撤销的动作说了算）。
- 顶部“今天”的数字：自动收录、接受、拒绝、驳回来自它；确认发布来自 `publications`（今天、状态 published）；用时是两者人工秒数之和。
- 总协调读 `send_back` 行，把事派回对应角色。
- 和账本一样只追加；撤销也是追加一行。

## 8. 空、出错、加载

| 情况 | 显示 |
| --- | --- |
| 队列清空 | “没有待确认的结论。今天确认发布 7 条，退回 2 条。”/“候选都处理完了。今天接受 86 条，拒绝 31 条。”+ 另一个队列剩几条，`Q` 切换 |
| 只剩跳过的 | “剩下的 12 条都是跳过的。”照常显示第一条 |
| 写入失败（数据库锁、规则拒绝） | 停在当前条，不前进，顶部写数据库返回的原因原文和“什么都没有写入” |
| 5 秒等待中写入失败 | 回到那一条，写明原因 |
| 原件、转写、凭据包文件缺失或哈希不符 | 对应栏里写明是哪个文件、什么问题；该条停用，可跳过 |
| 服务没在运行 | 浏览器打不开页面；终端里有一行启动命令（开发定） |

## 9. 代码的中文名（只用在审核台）

类型：promise 承诺，prediction 预测。可验证性：measurable 可量化，vague 含糊，hedged 有保留。
期限依据：stated 原话写明，inferred 推断。结论（决策 0008 的中文名）：无法验证、待定、待评估、成真、部分成真、未成真。

## 10. 安全（交给开发和关键审查）

只监听 `127.0.0.1` 还不够：创始人浏览器里打开的任何网站都能向 `localhost` 发请求。
所以写操作（尤其是确认）必须带一个启动时随机生成的令牌（终端打印带令牌的网址），并检查 `Host` 和 `Origin`；
没有令牌的请求一律拒绝。这一块按 `team/README.md` 属于“影响什么能公开”，审查时请用 Fable 5.2（或当天的 Opus 代审）。

## 砍掉的（原则 5）

- 批量操作（例如“一键拒绝全部 48 条重复”）：每条至少看一眼，重复标记已经让它成为两个键的事。
  若创始人觉得重复太多，可以以后加，前提是先在审核记录里看到他对重复标记的同意率。
- 搜索、筛选、排序选项、统计图、多用户、登录：一个人、一台电脑，不需要。
- 原件 PDF 的页面渲染：右栏用转写文本，因为程序就是拿它核对原话的；要看排版按 `O`。
- 确认框：用 5 秒可撤销代替。
- 结论队列的计时显示。
- 进度条：只写 n / N。

## 依据哪条原则

- 7（能自动就不手动）：一键一动作、预填理由、同页候选连排、自动计时、只把机器做不了的判断留给人。
- 2（无源不录）：原话旁边就是原件那一页；结论旁边就是凭据摘录和发布检查；核对不过的不能接受、不能确认。
- 1（问题和结论一样重要）：“待评估”的“还缺什么”在评审票和发布内容里都直接显示；退回必须写一句缺什么。
- 3（一把尺子）：六种结论同一样式，“未成真”没有警示色；一致与否用文字。
- 5（最简方案）：复用网站样式；不加表，只加一个只追加的文件；砍掉的见上。
- 6（有话直说）：见下。

## 异议与风险

1. **候选没有说话人。** `claims.subject_id` 必填，但候选文件和复查文件里都没有人物编号。我建议候选文件在文件一级加
   `subject_id`（由抽取角色填写，`checkCandidatesFile` 检查它存在）；这是文件格式，不动 `db/schema.sql`，但要总协调派给开发。
   没有它，审核台只能每份来源问一次“说话人是谁”，多一步手工。
2. **评审票的说明不在数据库里。** `jury_votes` 只有 `reasoning` 和一种语言的 `open_question`，没有 `summary_fr/en`；
   这些只在投票文件里（`answerOf`）。审核台要并排显示说明并在“采用第 n 票”时拷进 `verdicts`，就必须读投票文件。
   能用，但工作区里同一票分两处放。是否给 `jury_votes` 加两个字段，请总协调决定（我不改记录格式）。
3. **翻译必须在进入结论队列之前做完。** 发布检查要求每段凭据摘录都有另一种语言的译文，而凭据包和评审票里没有。
   如果翻译排在审核台之后，几乎每条都会卡在“双语”上，创始人只能一条条退回。建议流水线顺序：评审 → 翻译 → 审核台。
4. **拒绝、跳过、退回不进数据库**，只在 `data/desk/actions.jsonl`。它和数据库一样只在本机，但备份方案要把它算进去。
   另一种做法是加一张 `desk_actions` 表；我选了文件，因为它不碰已经过四轮审查的记录格式。
5. **一致的条目会被“顺手”确认。** 把一致的排在前面最快，也最容易形成不读就按的习惯；而“全体一致自动通过”
   正是要靠这段时期创始人的真实判断来校准（决策 0003）。缓解：不显示计时；警示框不可关闭；5 秒窗口。
   更强的做法（不在这一版）：每 20 条一致的，随机隐藏一次票数，先让他自己选结论再揭晓。
6. **“采用多数票”是默认值。** 默认值会影响判断。三票各不相同时不预选；2 : 1 时预选多数，这是速度和中立之间的取舍，
   如果创始人不同意，可以改为分歧时一律不预选。
7. **`decided_by` 的含义**：我定为“只改说明文字仍算 jury，改了结论才算 human”。这影响以后“评审团和人对得上吗”的统计，
   请总协调确认这个口径。
8. **17 px 一种正文字号放在 768 高的屏幕上**，结论页要滚动一屏多。操作栏固定在底部，所以不用滚到底才能按；
   但三栏评审说明较长时，右栏会比左栏高。没有在浏览器里实测。
9. **安全**（§10）：本地服务也会被浏览器里的网页调用，令牌和来源检查不能省。
10. **自动收录（总协调的改动，我同意方向，记下三点风险）。**
    a) 现在复查标记成了唯一的闸门：标记漏掉的非承诺会直接进工作区，再花一轮剪凭据包和三票评审，到 B 才被驳回。
    钱不多（订阅加一票 API），但浪费的是夜里的订阅额度。缓解：顶部每天显示“自动收录”数；
    每周从审核记录统计“自动收录后被驳回”的条数，偏高就收紧进队列 A 的条件。
    b) 驳回删除工作区数据，评审团在这条上的投票也一起删；我把它们存进审核记录的 `removed`，不丢。
    如果总协调认为删除不合适，替代是给 `claims` 加一个“已驳回”状态，那要改记录格式，由总协调定。
    c) 队列 B 现在要同时回答两个问题（该不该收录、结论能不能公开），每条会更慢；自动收录省下的时间有一部分会挪到这里。
    “原件这一段”默认折叠，只有需要时才看，以免每条都多读一屏。

## 没做的和没验证的

- 没在浏览器里实测排版、焦点顺序和 200% 缩放；没跑 accessibility-review。
- 编辑表单（候选 `E`、结论 `E`）和快捷键一览（`?`）只在文字里规定，没画。
- 每周人工用时报表（原则 7 的落地）不在本稿范围，数据来源已在 §6、§7 定好。

## 总协调的决定（2026-11-22）

1. 候选文件在文件一级加 `subject_id`（文件格式，不改记录格式）。
2. 评审票的法英说明不进数据库，审核台从投票文件读取（`data/candidates/packs-*/`）。
3. 流水线顺序：评审 → 翻译 → 审核台。
4. 拒绝、跳过、退回、驳回、自动收录记在只追加的 `data/desk/actions.jsonl`，备份要包括它。
5. 驳回从工作区删除该条（连同结论、凭据、评审票），删除前完整写进审核记录，Z 可以放回。账本不受影响。
6. `decided_by`：只改说明文字仍记 jury；改了结论记 human。
7. 2:1 分歧时**不预选**任何一票（避免默认值左右判断，这段时期的判断要用来校准评审团）；三票一致时预选那一票。
8. 本地服务器的安全要求（启动令牌、检查 Host 和 Origin、只监听 127.0.0.1）按关键审查处理。
