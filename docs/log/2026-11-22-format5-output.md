- 角色：开发

- 日期：2026-11-22
- 经过：初版 → 两处跟进修改 → 结论必须附说明 → 独立审查第一次退回后的修改。下面“做了什么”写的是**现在的状态**；
  各轮改了什么在文末的补充里。

## 做了什么（当前状态）

`db/schema.sql`，记录格式 5：

- **人物编号。** `subjects.id` 是公开的永久编号，改成 `INTEGER PRIMARY KEY AUTOINCREMENT`（数据库不会把删掉的编号自动再发出去），
  加一个触发器 `subjects_id_fixed` 拒绝修改编号。这是工作区里唯一的触发器。
  可选的 `wikidata_id`：为空，或 `Q` 加不以 0 开头的数字；不为空时唯一。快照的 `subject` 带 `id` 和 `wikidata_id`。
- **语言代号。** `claims.lang` 和 `sources.lang` 都是两个小写字母的 ISO 639-1 代号（`fr`、`en`、`de`…）。
- **双语字段。** 我们自己写的文字分法、英两列：`speaker_role_fr/_en`、`criteria_fr/_en`、`summary_fr/_en`、`open_question_fr/_en`。
  引用的文字保留原文（`quote_original`、`excerpt`），旁边存译文 `quote_fr/_en`、`excerpt_fr/_en`，
  **不存译成原文语言的那一份**：法语原话的 `quote_fr` 必须为空（行约束），法语来源的摘录 `excerpt_fr` 必须为空（发布时检查）。
  `jury_votes.open_question` 仍是单一字段，它不进快照，不公开。
- **行约束（工作区）。** 可衡量的承诺至少一种语言写了判定标准；“无法判定”至少一种语言写了还缺什么。另一种语言可以后补。
- **领域。** 固定清单 20 项（创始人 2026-11-22 确认）：economy、tax、employment、health、education、environment、energy、
  security（只指国内安全）、defence、justice、immigration、foreign_affairs、institutions、social、housing、transport、
  agriculture、digital、culture、other。
- **“空白”的定义。** 全文统一一份字符表：普通空格、制表、换行、垂直制表、换页、回车、U+0085、U+00A0、U+1680、
  U+2000 到 U+200B（含零宽空格）、U+2028、U+2029、U+202F、U+205F、U+3000、U+FEFF（BOM）。
- **发布条件**（`publication_checks`，接入 `publishable`）：
  - `question_stated`：“无法判定”至少一种语言写了还缺什么。
  - `summary_stated`：断言结果的结论（kept、partly_kept、not_kept、condition_unmet）至少一种语言写了说明（创始人定的“必须附说明”）。
  - `bilingual`：
    - 引文：原话不是法语就要有 `quote_fr`，不是英语就要有 `quote_en`；
    - 每条证据摘录：来源不是法语就要有 `excerpt_fr`，是法语就不能有；英语同理；
    - 我们自己写的每一对（发言身份、判定标准、说明、还缺什么）都是“两种语言都有或都没有”，不管结论和可衡量性是什么。
      和上面的“必须有”合起来，必须有的就必须两种语言都有。
- 来源类别注释：官方机构评价自己工作的材料登记为 `statement`（来源规则 0.3）。

其他文件：`src/db.js`（`SCHEMA_VERSION = 5`）；`src/ledger.js`（原因清单加 `summary_stated`、`bilingual`）；
`test/` 下的三个文件；`team/run/translate.md`、`team/run/extract.md`（0.2 版，见补充三）；`data/kanverify.db`（每轮先确认 0 行再重建）。

测试：`npm test` 60 个全部通过。每条发布规则都做了反向验证（见补充三）。

## 依据哪条原则

- 原则 2（无源不录）：原话和证据原文保留原语言，译文另存，不替换原文；也不把原文抄进译文栏冒充译文。
- 原则 3（一把尺子）：法语站和英语站给出同样完整的信息；同一个缺口在两个站上一样处理。
- 原则 1：“还缺什么”两个站点都要写；断言结果的结论必须解释自己。
- 原则 5：没有加表和依赖。加了一个触发器，是总协调按审查意见要求的；一个只在关掉约束检查时才起作用、测不到的发布条件被删掉了（见补充三）。

## 异议与风险

1. **人物编号仍然可以被显式复用。** `AUTOINCREMENT` 只保证数据库自己不再发出删掉的编号。用普通语句
   `INSERT INTO subjects (id, …) VALUES (2, …)` 指定一个删掉的编号，数据库照样接受（已在本机验证）。
   另外 `UPDATE sqlite_sequence` 也能把计数器调回去。要堵住第一种，需要再加一个插入时的触发器；
   这次任务只要求一个触发器，所以没加，等总协调决定。
2. **工作区现在有了一个触发器。** 决策 0005 写的是“工作区没有任何触发器”。`subjects_id_fixed` 只管一件事，不挡正常修改，
   但 0005 的文字需要总协调更新。
3. **证据摘录“不能有原文语言的译文”只在发布时检查。** 这取决于另一张表（来源的 `lang`），行约束看不到别的表，
   不用触发器就做不到行级检查。所以工作区里可以存一份多余的 `excerpt_fr`，到确认时才被挡住。
   反过来，改了来源的 `lang` 也会让已经合格的摘录变得不合格，审核台会显示原因。
4. **引文的语言规则只认 `fr` 和 `en`。** 其他语言的原话（如 `de`）两份译文都要。这是对的，但翻译工作量也在这里。
5. **设计稿和决策记录里的字段名过时。** `design/ia.md`、`design/DESIGN.md` 还在用 `claim.speaker_role`、`claim.criteria`、
   `verdict.open_question`，也没写“法语原话没有 `quote_fr`”。网站要把 `quote_original` 当作原文语言那一版显示，
   另一种语言显示译文并标明。`docs/decisions/0005` 还写着 `claims.speaker_role`。这些我按要求没动。
6. **这是“什么能公开”的改动。** 需要 Fable 5.2 再做一次只查改动的审查。我没有审查自己的代码。
7. 说明只检查“有没有”，不检查写得好不好。说明的质量仍然靠人工确认和中立性审查。

## 格式 6：结论统一为五种（决策 0008，判定标准 0.2 第 2、5 节）

上面“当前状态”里关于结论的部分以本节为准。

- `verdicts.verdict` 和 `jury_votes.verdict` 只能是 `unverifiable`、`pending`、`to_evaluate`、`came_true`、`not_came_true`，
  取代原来的六种。`SCHEMA_VERSION = 6`，没有迁移代码，数据库确认 0 行后重建。
- 原来“无法判定”的规则全部移到 `to_evaluate`：行约束至少一种语言写了还缺什么（结论表和评审团投票表都是），
  `question_stated` 同样，两种语言由 `bilingual` 在发布时要求。
- `summary_stated`：除 `pending` 外每种结论都要有说明（`unverifiable`、`to_evaluate`、`came_true`、`not_came_true`），两种语言由 `bilingual` 要求。
- `outcome_has_evidence` 适用于 `came_true` 和 `not_came_true`。
- **新增一列 `verdict_fits_verifiability`**：可验证性是 `vague` 或 `hedged` 的条目只能以 `unverifiable` 发布；
  `measurable` 的可以是任何结论（包括条件没有出现时的 `unverifiable`）。
  单独一列而不是并进已有规则，理由和 `summary_stated` 一样：它是一条独立的判定规则，审核台要给出能照着改的原因
  （“含糊或有保留的条目只能判无法验证”），并进别的列会给出错误的提示。它是跨表的（看承诺和结论两张表），所以只能在发布时查，不做行约束。
  已发布的条目改成 `vague` 之后，显示“有未确认的改动”，并且不能再确认。
- `src/ledger.js`：原因清单加 `verdict_fits_verifiability`，`question_stated`、`summary_stated` 的说明改成新叫法，三者都在“需要先有结论”那一组。

### 格式 6 的异议与风险

1. **“本人明确放弃 → 未成真”和来源规则冲突。** 决策 0008 说放弃的凭据是放弃的原话出处，但那是当事人自己的话（`statement` 或 `platform`），
   `evidence_is_primary` 不允许它作凭据，`outcome_has_evidence` 也不认它。所以现在以放弃为理由的“未成真”发布不了。
   我没有改来源规则（属于创始人）。`team/run/judge.md` 里暂时写成：判 `to_evaluate`，在还缺什么里写明放弃的原话出处。需要创始人定。
2. **“未成真”和“成真”没有检查期限。** 判定标准说到期才判，推定的期限不能用来提前判“未成真”。数据库没有检查结论和 `deadline` 的关系（任务没要求）。
   `pending` 也没有检查“期限未到”。
3. **评审团投票的“待评估”只要求一种语言的还缺什么，投票不要求说明。** 投票是工作数据，不公开，所以这样做是对的；写在这里免得以为漏了。
4. 部分做到也是“成真”（决策 0008 已记录的风险）：数据库只能保证有说明，不能保证说明写出了做到的程度。
5. 这是“什么能公开”的改动，需要 Fable 5.2 审查。我没有审查自己的代码。
