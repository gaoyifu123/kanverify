# 产出：MVP 设计规范冻结（视觉稿第三版）

- 角色：设计（建造组子 agent）
- 模型和提示词版本：Opus 5.5；不适用（建造组）
- 日期：2026-11-22

## 做了什么

创始人对第二版的意见是“方向对，继续”，并要求：少用不同的字号和字重，先做出 MVP；兼顾宽屏用户。
同时，决策 0008 把结论定为五种，记录格式已升到第 6 版。这一版按这些要求改完，并冻结成给开发的 MVP 规范。

1. **字号字重。**
   - 只留两个字号：17 px 用于所有文字，24 px 只用于页面标题和年份。
   - 只留两个字重：400 和 600。
   - 去掉了小字号，次要信息改用浅一档的墨色区分。
   - 衬线体只用于“别人说的话”。理由：它表示“这是他们的原话，不是我们写的”，有含义，不是装饰，而且不增加字号字重。
   - 标题改回无衬线体。
2. **五种结论。** 改了以下文件：
   - `DESIGN.md`、`ia.md`、`components.md`、`tokens.md`；
   - `sample-data.js`（旧值按 0008 映射）、`stats.js`、`topic-view.js`；
   - 全部视稿，花纹从六种改为五种。

   展示规则：
   - “待评估”一定显示“还缺什么”；
   - “无法验证”显示摘要，说明原因；
   - 含糊和有保留的条目一律是“无法验证”，“依据”一行写“话本身的措辞”。

   方法页加上了“本人公开放弃”这类来源。
3. **冻结为 MVP 规范。**
   - 新增 `design/tokens.md`、`design/components.md`。
   - `design/ia.md` 写明了生成器要输出的全部文件：路径、数量、每页显示哪些账本字段、`index.json` 的字段，
     以及“撤回条目的快照不能进入任何公开文件”。
   - 法英两种视稿同步：首页、人物、话题、条目、方法页都有两种语言。
4. **宽屏。**
   - 1024 px 起：人物页和话题页是“统计 | 列表”两栏，条目页是“摘要层 | 详细层”两栏，首页卡片两列。
   - 1440 px 起：卡片三列，列表两列。
   - 正文行宽始终不超过 44rem。
   - 时间轴按实际像素宽度绘制，所以在任何屏幕上文字都是 17 px。
5. **清理。** `kanverify.css` 整个重写，删掉了第一版留下的无用样式：侧边目录、计数格子、搜索框、证据块、大号结论框、小字号。

**没有验证的：**
- 没有跑任何自动检查；
- JavaScript 没有实际运行过，只是照着代码在脑子里走了一遍；
- 没在浏览器、手机、读屏软件上看过；
- 对比度是按色值手算的；
- 法语没有母语者校对。

## 依据哪条原则

- 原则 3：一种结论框、一种墨色、互为镜像的花纹、一套用词、中性排序、不给比例。
- 原则 1：“待评估”的“还缺什么”永远留在第一层。
- 原则 2：“依据”一行紧跟在结论后面。
- 原则 5：两个字号、两个字重；样式表瘦身；生成器只读一份 JSON 索引。
- 原则 8：不使用任何第三方资源。

## 异议与风险

1. **“成真”现在包含“部分做到”（决策 0008），这是图表里最大的诚实风险。**
   “建了 1000 套里的 100 套”和“1000 套全建了”是同一个结论框、同一种花纹。
   条目页上，说明紧跟在结论下面，并且必须写明做到了多少；但人物页的环形图和话题页的并排条表达不出来。
   我照决定执行，并建议：上线后一旦有真实数据，先看“成真”里部分做到的占多少；如果占比大，再回来讨论是否单列。
2. **“无法验证”混了两种不同的情况：** 话说得含糊，和所附的条件没有出现。
   在计数里两者一样，所以一个说了很多附条件承诺的人，看起来像是“说话含糊”。摘要会写明是哪一种，但图表看不出来。
3. **去掉小字号的代价：** 元数据和正文一样大，手机上每一行会更长，滚动更多。为了看着不累，我接受这个代价。
4. **衬线体是我自己的判断。** 创始人要求少用字体变化。我保留衬线体只用于引文，理由见上。
   如果创始人觉得仍然太花，可以统一成无衬线体，代价是“原话”和“我们的话”少了一个一眼能分清的标志。
5. **宽屏的两栏布局：** 人物页把统计放左边，读者往下滚到列表底部时，左边的筛选就看不到了。
   我没有做左栏固定，因为左栏太长时，固定会把内容截掉。
6. **生成器必须从所有公开文件里剔除撤回条目的快照**，包括 `index.json`，否则就会公开创始人决定隐藏的内容。建议为此写一条测试。
7. **仍未解决：**
   - 撤回原因只有一种语言；
   - 记录里没有中立性审查的结果；
   - 更正邮箱还不存在；
   - 判定标准文件要和五种结论对齐（应已由总协调处理，我没有核对）；
   - 预测怎么判的细则还没定。
8. **视稿数据和 `index.json` 规范有一处不一样：** 发言身份在视稿里用的是 `role` 键，规范里写的是 `role_fr`/`role_en`，以规范为准。

## 和现有网站的区别

- **Lui Président**：它每位领导人一块，配插图。我们以时间轴为主，没有插图，结论顺序固定。
- **PolitiFact**：它有计量表、百分比、照片，凭据放在另一篇文章里。我们这些都没有，凭据就在条目页上。
- **Polimeter 一类的政府追踪器**：它们只追一届政府，用颜色分级。我们跨人、跨国，不用颜色。
- **Histography**：只借了“线上的点、可以拉动的时间范围”，没有借它满屏的历史画布。

  - 第一版留下的无用样式。
- **之前几版砍掉的：**

  - “浏览”页；
  - 结论图标；
  - 两套结论用词；
  - 人物页上的撤回条目。
- **挪到下一层的：** 证据原文、指纹、出处、判定标准、评审团、历史、期间筛选、话题页的数字表格。
