# 产出：静态网站生成器（src/site.js）

- 角色：开发（建造组）
- 模型和提示词版本：Opus 5.5（建造组，不适用运行组提示词版本）
- 日期：2026-11-22

## 动手前想清楚的（原则 4）

- 要改什么：新增一个生成器，只读账本（`publications`，经 `current_publications` 判断当前状态），按 `design/ia.md` 第 2 节输出法语和英语两套静态文件。
- 为什么这样做：不能公开的东西（撤回的快照、被撤回的那次发布、`confirmed_by`、`review_seconds`）在**读账本的那一条查询里**就去掉，后面的页面代码根本拿不到。这样“撤回的内容不出现在任何文件里”只取决于一处，而不是靠每个页面各自小心。
- 不加什么：不加依赖、不加表、不加构建步骤。样式表和 `theme.js` 在构建时从 `design/mockups/` 原样复制，方法页从 `method.{lang}.html` 的 `<main>` 取出；视觉稿脚本里必须为真实数据改的部分（数据来源、链接、发言身份、国家名）放在一个改写过的文件里。

## 做了什么

- 新增 `src/site.js`：
  - `buildSite(db, outDir, { today })`，返回 `{ files, items, claims, subjects }`。`today`（YYYY-MM-DD）只决定首页不开 JS 时打印哪一年的卡片，默认本机日期。
  - `readLedger(db)`：一条 SQL 读全部账本，同时把以下内容置空：撤回记录的快照；紧接着被撤回的那次发布的快照；当前状态是“已撤回”的条目的所有快照。`note` 只对撤回记录取出。从不选取 `confirmed_by`、`review_seconds`。整个过程只有 SELECT。
  - 输出（每种语言一套）：首页、20 个话题页（空的也生成）、每个有已发布条目的人物页及其不带名字的跳转页、每条进过账本的条目页（已撤回的只有通知、日期、原因和日期历史）、方法页、更正页、`index.json`；外加根目录语言选择页、`assets/kanverify.css`、`assets/site.js`。
  - 不开 JS 也能读：首页打印当年按到期日的卡片和人物列表；话题页打印该话题全部条目（按人物、再按发言日期）、各人五种结论的计数（文字和表格）；人物页打印五种结论计数、话题计数和全部条目（按话题名、发言日期、编号）。脚本加载后再替换。
  - 转义：所有文字经 `esc()`（`& < > " '`）。只有 http/https 地址变成链接，其他地址原样显示为文字。`index.json` 里的 `<` 写成 JSON 转义（反斜杠 u003c），文件即使被嵌进页面也不会被当成标签。
  - 引文：原话带 `lang`；页面语言不同时才显示该语言译文，并标“Translation from …/Traduction de …”。我们自己写的成对文字（发言身份、判定标准、结论说明、还缺什么）两种语言都有才显示，否则两个站点都不显示。
  - 输出目录：先确认它是空的或带有生成器写的标记文件 `.kanverify-site`，再整个清空重建（防止上次构建留下的、本该消失的人物页继续存在）；别人的非空目录拒绝动。
  - 命令行：`npm run site` 用 `data/kanverify.db` 构建到 `dist/`；数据库文件不存在时报错退出，不会新建。
- 新增 `src/site-assets/views.js`：从 `stats.js`、`person-view.js`、`topic-view.js` 改写，文件开头列出了和视觉稿的每一处差别。构建时和 `design/mockups/theme.js` 拼成 `assets/site.js`。
- `package.json` 加 `"site": "node src/site.js"`；`.gitignore` 加 `dist/`。
- 新增 `test/site.test.js`（11 个测试，内存数据库，全部经 `src/ledger.js` 的 `confirm`/`withdraw` 建账本）：
  - 输出文件集合与 ia.md 完全一致（多一个少一个都失败）；
  - 两种语言都生成、各用各的标签；原话 `lang` 和译文标注；
  - 人物页、话题页的五种结论计数与 `current_publications` 一致，`index.json` 的条目和字段与 ia.md 一致；
  - 撤回条目：在快照、证据摘录、来源标题、地址、人物名、两次确认的说明里都放了唯一标记，遍历输出目录的每个文件都找不到；它的人物没有页面，首页没有，更正页只写“Published → Withdrawn”和原因；
  - 确认后在工作区改的内容、从没确认的条目、`confirmed_by` 都不出现；
  - 含 `<script>` 的引文被转义，`javascript:` 地址不成为链接；
  - “待评估”在摘要层显示“还缺什么”，历史显示两次；首页打印当年卡片和人物；拒绝清空别人的目录、清掉自己上次的残留。
- `npm test`：117 个全部通过（原 106 + 新 11）。`npm run site` 在本机空账本上跑通（51 个文件），产物已删除。

## 依据哪条原则

- 2 无源不录：网站只从账本生成；每条结论旁边有“依据”，详细层有地址、取得日期和哈希。
- 3 一把尺子：五种结论同一种样式、计数含零；成对文字缺一种语言时两个站点都不显示，保证两边内容一样；撤回的条目不进任何列表和计数。
- 1 问题和结论一样重要：“待评估”的“还缺什么”始终在摘要层。
- 5 最简方案：零依赖、无构建步骤；样式和方法页直接取自视觉稿，不复制两份。
- 8 不受制于人：页面不请求任何外部资源；只读本机数据库。

## 异议与风险

1. **撤回原因只有一种语言，而且没有语言字段。** ia.md 要求“原因的语言和页面不同时注明”，但 `publications.note` 不记录语言，我无法判断，只能原样显示，不加 `lang`、不注明。需要设计或记录格式决定（我不能改 `db/schema.sql`）。
2. **人物名、文件标题没有语言字段。** 视觉稿在英文页给法语党名加了 `lang="fr"`，账本里没有依据，我去掉了。文件标题我按来源的 `lang` 标注，这是假设标题和原件同一种语言。
3. **ia.md 没有话题总页。** 页眉和页脚的“话题”链接没有目标，我指向 `topic/economy/`（记录格式里的第一个领域，两种语言一致，不按内容挑选）。建议设计补一个 `/{lang}/topic/` 或明确定下默认话题。
4. **更正邮箱是视觉稿里的占位地址** `corrections@example.org`（`src/site.js` 的 `CORRECTIONS_EMAIL`）。对外发布之前必须换成真实地址。
5. **更正页和历史比 ia.md 更严。** ia.md 写“结论 前 → 后”。如果某次发布后来被撤回，它的快照就是被撤回的内容，所以这一次我只写“Published/Publiée”，不写结论；当前已撤回的条目，更正页上一个结论都不写。这是我对“撤回内容不留痕迹”的理解，请设计或创始人确认。
6. **几段没有设计稿的文字是我写的**：更正页的说明、历史摘要（“Updated n times since …”）、`decided_by` 的说法（“Verdict written by a person / proposed by the AI jury”）、根目录语言选择页、跳转页。请设计审一遍措辞。
7. **评审团表格的“公司”一栏显示的是 `provider` 的原值**（如 `provider-a`），视觉稿里是公司名。账本里没有公司显示名，接口层定下供应商代号后需要一张对照表。
8. **视觉稿的期限标签对预测不太合适**：“déduite : fin du mandat”“fixée dans la promesse”用在“预测”上不通。照视觉稿做了，请设计决定。
9. **同一人物在不同快照里名字可能不同**（确认之后改过名）。页面统一用该人物最新一次当前发布里的名字，网址只认编号。
10. **浏览器脚本没有在浏览器里测过。** 测试环境没有 DOM，只做了语法检查；`views.js` 基本照搬视觉稿，改动列在文件开头。另有一处小改：时间轴滑块的范围扩到包含当年，否则“今年”在数据范围之外时滑块会被截断。
11. **首页不开 JS 时的“今年”是构建时的年份**，开 JS 后用读者的日期。跨年后不重新构建，不开 JS 的读者看到的是去年的卡片。
12. 方法页和样式表在构建时从 `design/mockups/` 读取，构建依赖设计目录；视觉稿改了，下次构建网站就跟着变。我认为这是想要的（单一来源），但设计改稿时要知道这一点。
13. 生成器决定“什么出现在公开文件里”，按 `team/README.md` 属于影响“什么能公开”的改动，建议这次代码审查用 Fable 5.2（额度不足时按 11-22 的决定由 Opus 代审并在摘要里写明），范围限于 `readLedger` 和撤回条目的输出路径。

### 做了什么

1. **两条置空规则各有一个专门的测试。**
   - 新数据 7：同一条先发布（成真）、撤回、再确认（未成真），即“发布、撤回、发布”。断言两种语言的条目历史和更正页里都没有“成真/Réalisée”，第一次发布只显示“Published/Publiée”。

3. **“原始地址”**：链接指向规范化后的地址，显示的文字是记录里存的原文（转义后）。测试用 `HTTPS://Example.ORG/p2 path` 验证：链接是 `https://example.org/p2%20path`，显示原文。
4. **没有标签的代码让构建失败**：读完账本后、写任何文件之前，检查每个能显示的快照里的领域、类型、可验证性、结论、人物类型、来源类型（出处和每条证据）、评审团投票结论在两种语言里都有标签，期限依据只能是 stated 或 inferred。报错会写明是哪条账本记录、哪个代码。测试用一个只返回一行账本数据的替身数据库（领域写成 `space`，或证据类型写成 `rumour`），断言报错、上一版网站一字不变、没有留下临时目录。另有一个测试让某页在生成时出错（发言日期为空，能通过标签检查），验证第 2 点。
   - 这两条也做了变异检查：去掉标签检查，或改回直接写进输出目录，各自只有对应的测试失败。

### 依据哪条原则

- 2 和 3：撤回的内容在任何页面上都不留结论，现在每条规则都由一个测试守着。
- 4：每条规则都要有一个删掉它就会失败的测试，这次用变异检查确认了。

### 异议与风险

- 替换不是严格的原子操作。在“旧目录移开”和“新目录放进来”之间，输出目录有一瞬间不存在。本地构建用的 `dist/` 没有影响；以后如果有程序在构建时同时读这个目录，需要再议。

- 替身数据库测试依赖 `readLedger` 只用 `prepare().all()` 这一种调用。以后改读法时，这两个测试要跟着改。

## 补充二：换目录失败时的清理（2026-11-22，开发，Opus 5.5）

- 原来换目录的两次改名不在 try/catch 里，改名失败（例如文件被占用，EPERM）会把完整的 `.dist.build-*` 留在项目根目录。现在任何一次改名失败都会把旧网站放回原处、删掉新建的目录，并报一个写明原因的错误（“Could not replace … (EPERM). The previous site was kept.”）。`buildSite` 多了一个只给测试用的 `rename` 参数，用来模拟改名失败。`.gitignore` 加了 `.dist.build-*/` 和 `.dist.old-*/`。
- 新测试分别模拟第一次改名失败（移开旧网站）和第二次改名失败（放入新网站）：上一版网站不变，旁边不留任何目录。变异检查：去掉清理，这个测试失败。`npm test` 123 个全部通过。
- 异议与风险：如果把旧网站放回原处这一步也失败了，旧网站会留在 `.dist.old-*`（已被 git 忽略），需要人手动改回名字。
