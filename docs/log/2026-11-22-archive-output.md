# 产出：获取角色的存证步骤（src/archive.js）

- 角色：开发（建造组）
- 模型和提示词版本：Opus 5.5（建造组，不适用运行组提示词版本）
- 日期：2026-11-22

## 做了什么

- 新增 `src/archive.js`：
  - `archive(db, { url, kind, title, publisher, published_on, lang }, { fetchImpl = fetch, evidenceDir, maxBytes, timeoutMs })` → 新来源的 id。
  - 只接受 http/https；其他协议和非法地址在发请求之前就拒绝。
  - `redirect: 'follow'`，超时 60 秒（`AbortSignal.timeout`，下载正文期间也生效），上限 50 MB：先看 Content-Length，读取时再逐块计数，超了就停。
  - 非 2xx 拒绝；Content-Type 去掉参数、转小写，空的或不像 `类型/子类型` 的拒绝；空文件拒绝。
  - 边读边算 SHA-256，写进同目录的 `.tmp-<uuid>`，完成后改名为 `<sha256>.<扩展名>`。扩展名只来自代码里的固定对照表（不认识的类型用 `bin`），文件名里没有任何来自地址或响应头的文字。同一哈希的文件已存在就直接复用、删掉临时文件。任何失败都会清掉临时文件。
  - `retrieved_on` 为本地日期 YYYY-MM-DD。写库经 `openDatabase` 打开的连接，约束全部由 `db/schema.sql` 把关，代码里没有另外放宽或重复。
  - 导出 `evidencePath(dir, sha256, mediaType)`，只接受 64 位小写十六进制。
  - 命令行：`npm run archive -- <url> --kind ... --title ... --publisher ... --lang ... [--published-on ...]`，打开默认数据库，打印来源 id 和文件路径。参数解析用内置 `node:util` 的 `parseArgs`。
- `package.json` 增加 `"archive": "node src/archive.js"`。
- 新增 `test/archive.test.js`（9 个测试，全部用注入的假 fetch 和临时目录，不联网）：按哈希存文件并登记来源；去掉媒体类型参数；同内容两次复用同一文件；非 http 地址不发请求即拒绝；超大正文（流式和 Content-Length 两种）拒绝且不留文件；缺少或空 Content-Type 拒绝；HTTP 错误和空正文拒绝；文件不出 evidenceDir（含 `text/../../evil` 这类类型被拒、`evidencePath` 拒绝非哈希）；数据库拒绝的行不登记。
- `npm test`：51 个测试全部通过（原有 42 个 + 新增 9 个）。没有这个模块时新测试无法导入，必然失败。
- 没有新增依赖、表或构建步骤：`sources` 表已有所需的每一列，只用了 Node 内置的 fetch、crypto、fs、path、url、util。

## 依据哪条原则

- 2 无源不录：每条来源都指向一份本地持有、以哈希命名的原件；下载失败如实报错，不兜底。
- 5 最简方案：一个模块、一个函数，不加依赖和表；扩展名用固定对照表而不是解析地址。
- 8 不受制于人：零依赖，文件只存本机；不涉及 AI。

## 异议与风险

- **记录的是请求的地址，不是跳转后的最终地址。** 我按任务单“record the URL actually requested”和 fetch.md 的“原始地址”理解为调用方给的地址（规范化后）。跳转后的最终地址目前没有地方存（`sources` 没有这一列），审计时可能想要它。是否要加，请创始人/总协调决定；我没有改 schema。
- **跳转目标没有再检查。** Node 的 fetch 只跟随 http/https 跳转，所以不会落到 file: 等协议；但跳到内网地址（如 127.0.0.1）不会被拦截。目前只在本机由人手动运行，风险低；若以后自动处理外部给的地址，需要再议。
- **文件先落盘、后写库。** 若数据库拒绝这一行（如 kind 写错），哈希文件会留在 evidence 目录里，没有对应的来源行。文件按哈希命名、无害，但会积累孤儿文件。没做提前校验，是为了不在代码里复制 schema 的规则。
- **同内容、不同 Content-Type** 会得到两个文件（例如 `x.pdf` 和 `x.bin`），内容相同。罕见，未处理。
- **复用已有文件时不重新校验其哈希。** 假设 evidence 目录只由本模块写入。
- 本模块处理下载的文件，按 `team/README.md` 属于“涉及安全的改动”，建议这次代码审查用 Fable 5.2。

## 没做的和没验证的

- 没有下载任何真实文件，没有联网测试真实的跳转、超时和大文件行为（超时只验证了把 signal 传给了 fetch）。
- 命令行只验证了无参数时打印用法（退出码 2）；完整命令行路径没有跑，因为会写默认数据库。
- 没有改 `db/schema.sql`、`src/ledger.js`；没有更新看板。

## 补充：按安全审查（Fable 5.2）修复（2026-11-22，开发，Opus 5.5）

### 做了什么

- `src/archive.js`
  - **跳转手动跟随**：`redirect: 'manual'`，最多 5 次（第 6 次报错）。`sources.url` 存**最终地址**，也就是字节真正来自的那个地址。没有改 schema。`archive()` 现在返回 `{ id, url, redirects, sha256, path }`，其中 `redirects` 是按顺序请求过的全部地址。命令行在有跳转时把这条链打印出来。
  - **地址检查（SSRF）**：每一跳之前用 `node:dns` 解析主机名（取全部地址），只要有一个地址属于以下任一类就拒绝：本机回环、未指定地址、私有网段（10/8、172.16/12、192.168/16、100.64/10）、链路本地（169.254/16、fe80::/10）、ULA（fc00::/7）、组播、保留网段（0/8、240/4、198.18/15、192.0.0/24、fec0::/10），以及它们的 IPv4 映射和兼容 IPv6 写法。判断看解析出来的地址，不看文字，所以 `2130706433`、`0x7f.1`、`017700000001` 都会被拦下。地址分类用内置的 `net.BlockList`。
  - **默认传输改用 `node:http`/`https`，不再用内置 fetch**。原因（原则 5）：fetch 在我们检查完之后会自己再解析一次 DNS，这中间存在 DNS 重绑定的空档；`node:http` 的 `lookup` 钩子能让同一套检查落在实际连接的地址上。这样做零依赖，大约多 30 行代码。对 `content-encoding` 不是 identity 的响应直接拒绝，不把压缩后的字节当原件存下来。
  - 测试注入：可以传 `resolver`、`fetchImpl` 和 `allowPrivate`。`allowPrivate` 默认是 false，只有测试为了连本机服务器才显式打开。
  - **文件名就是 `<sha256>`，不带扩展名**。删掉了 EXTENSIONS 表。`evidencePath(dir, sha)` 只接受 64 位小写十六进制。
  - **不信任已有文件**：每次都把刚算过哈希的临时文件改名覆盖到最终路径。如果那个位置是目录，改名会失败，于是整次存证报错。选覆盖而不选“读出来重算哈希再比较”，是因为覆盖更简单，而且任何时刻都不会出现“信任了没核过的字节”的窗口，也省掉一次最多 50 MB 的重读。
  - **状态码只收 200**，206、203、204 等一律拒绝。
  - 写盘后先 `fsync` 再关闭、改名。开始时清理一小时前留下的 `.tmp-*` 文件（只清普通文件）。写库失败、而且没有别的行用同一哈希时，删掉刚存下的文件。
  - 所有提前退出的路径都会取消响应正文并 abort 请求，不会挂到超时。
  - 带用户名或密码的地址一律拒绝（防止把凭据写进公开记录）。这一条是我额外加的，只有一行。
- `test/archive.test.js`：共 20 个测试（原 9 个改为无扩展名、注入假 DNS，新增 11 个）。新增的测试用 `node:http` 在 127.0.0.1 上起服务器，覆盖：跳转后存最终地址；超过 5 次跳转被拒；生产模式下跳到私有地址被拒；直接访问私有、回环和各种数字写法的地址被拒（含公私混合的 DNS 结果）；DNS 重绑定在连接时被拦；预先放进去的篡改文件被替换、同名目录导致报错；非 200 状态被拒；压缩编码被拒；写库失败不留文件（有别的行用同一哈希时保留）；提前拒绝时连接马上关闭；清理过期临时文件。测试不联网，假主机名都由注入的 resolver 应答，`localhost` 和 IP 字面量由系统解析器在本机应答。
- 变异检查：去掉 finally 里的取消和 abort，“提前拒绝时连接马上关闭”那项测试失败；去掉 `lookup` 钩子，“DNS 重绑定”那项测试失败。
- `npm test`：71 个测试全部通过。

### 依据哪条原则

- 2 无源不录：来源行记的是字节真正来自的地址，文件永远是刚核过哈希的那一份。
- 5 最简方案：只用内置模块（`net.BlockList`、`node:http`），不加依赖、不加表、不改 schema。改用 `node:http` 的理由见上。
- 8 不受制于人：零依赖；数据只在本机。

### 异议与风险

- **请求的原始地址没有入库，只在返回值和命令行输出里。** 按总协调的决定没有改 schema。但审计时可能想知道“创始人转来的是哪个链接”，现在这一信息只存在于终端输出里。建议以后再议是否加一列，或者另建跳转记录。
- **不再用内置 fetch，行为和浏览器会有差别**：不带 cookie，不自动解压，不走系统代理。如果创始人的电脑必须经代理上网，存证会失败。对强制返回 gzip 的服务器会直接报错，不会悄悄存下压缩字节。User-Agent 是通用的 `evidence-archiver/1`，有的网站可能因此拒绝访问。这些都会报错，不会存下错的东西。
- **没拦的地址类型**：NAT64（64:ff9b::/96）和 6to4（2002::/16）里嵌入的 IPv4 地址没有展开检查。这两类在家用 Windows 网络里很少见。
- **覆盖写的代价**：Windows 上如果最终文件正被别的程序打开（比如 PDF 阅读器），改名会因占用失败，整次存证报错，但不会留下坏数据。两个进程同时存同一份文件，或其中一个写库失败，理论上可能删掉另一方刚写的文件。目前只有一人手动运行，风险低。
- **fsync 没有覆盖目录项**：Windows 上不能对目录 fsync。断电时改名本身可能丢失，但不会留下半个文件，因为最终路径上只会出现完整核过的文件。fsync 本身没有测试能验证。
- **“没有别的行用同一哈希”只查传入的这个数据库。** 如果同一个 evidence 目录被另一个数据库共用，判断会不准。目前只有一个库。
- `archive()` 的返回值从数字改成了对象，调用方要改。仓库里目前只有命令行在调用。
- 这次又改了处理下载文件的代码，按 `team/README.md` 属于“涉及安全的改动”，建议复审用 Fable 5.2，范围限定为本次改动。

- 没有联网，没有对真实网址（https、真实跳转、大文件、超时）跑过。https 走的是和 http 同一条代码路径，只是换成 `node:https`，没有测试覆盖。
- 命令行只验证了不带参数时打印用法（退出码 2）。完整流程没跑，因为会写默认数据库。

## 补充二：复审发现的回归（2026-11-22，开发，Opus 5.5）

### 做了什么

- **R1（严重）**：有一类响应不写 Content-Length、也不分块，靠关闭连接表示正文结束。这类响应如果被超时或 abort 截断，`node:http` 销毁连接后正文看起来是“正常结束”，原来的代码会把半个文件当完整原件入库。现在读完正文后检查 `signal.aborted`，只要发生过超时或中止，整次存证报错，不留文件、不写行。测试：用原始 TCP 服务器慢速发送这种正文，超时设为 400 毫秒，结果是报错、目录为空、表为空。去掉这项检查后，该测试失败。
- **R2**：Transfer-Encoding 只接受缺省或恰好是 `chunked`，其他一律拒绝（例如 `gzip, chunked` 会把压缩字节当原件存下来）。测试覆盖了 `gzip, chunked` 被拒、普通 chunked 仍然能存。去掉这项检查后，该测试失败。
- **R3**：`isForbiddenAddress` 直接拒绝几类在 IPv6 里嵌入 IPv4 的前缀：64:ff9b::/96（NAT64）、2002::/16（6to4）、2001::/32（Teredo）、::ffff:0:0:0/96（SIIT）。只拒绝前缀，不展开里面的 IPv4。每类各测一个地址；去掉这些前缀后，测试失败。上一节“异议与风险”里关于 NAT64 和 6to4 的那一条到此关闭。
- `team/run/fetch.md` 加了一行已知局限：服务器自己提前断开、又不写长度的响应，在协议层面查不出来。存证文件被用作结论证据时，要由人打开核对。
- `npm test`：75 个全部通过，其中 `test/archive.test.js` 有 22 个。

### 依据哪条原则

- 2 无源不录：被截断或被编码过的字节不能当原件入库。
- 5 最简方案：前缀直接拒绝，不解析嵌入地址；截断只看一个信号位。

### 异议与风险

- 整个 2001::/32 和 2002::/16 都被拒绝。如果哪个真实网站只有 6to4 或 Teredo 地址，就存不了。这类网站如今几乎没有，而且失败会明确报错。
- 64:ff9b::/96 被拒绝后，如果创始人所在网络是纯 IPv6 加 NAT64（部分移动网络是这样），所有只有 IPv4 的网站都会失败。家用 Windows 网络一般不会这样，但换网络时要记得这一点。
- R1 的检查只能发现**我们这边**的超时或中止。服务器自己提前断开、又不写长度的响应，仍然查不出来，所以写进了 fetch.md 作为已知局限，靠人核对。
- 测试时间依赖 400 毫秒超时和每 50 毫秒写一次。机器很慢时可能误判；那时结果是“报错”而不是“存下”，所以只会误报失败，不会掩盖问题。

### 没做的和没验证的

- 仍然没有对真实网址跑过；https 路径仍然没有测试。
