# 0011 开源

- 日期：2026-11-22
- 状态：已定（创始人：“可以把这个做成开源的吧”）
- 依据：原则 3（一把尺子，规则公开可查）、原则 2（凭据和方法可核对）、原则 8（不受制于人）

## 决定

KANVERIFY 的代码、文档、方法和评审提示词公开在 GitHub 上。

- **代码：AGPL-3.0。** 别人可以用来做自己的网站，但改过的版本也要公开，防止有人改成不透明的版本。
- **文档和方法：CC BY 4.0。** 自由引用，注明出处。
- 许可证由总协调按上面的理由选定，创始人可以改。

## 不公开的

数据库、存证原件、候选数据、链接收件箱、`.env` 密钥：都在 `.gitignore` 里，只留在本机（原则 8）。
网站上的已确认条目本来就是公开的，由网站生成器发布，不经仓库。

## 公开前要做的

1. 隐私和密钥扫描（`docs/log/2026-11-22-open-source-scan.md`），按清单删改，创始人确认。
2. 涉及真实人物、尚未确认的结论（评审试跑、候选整理、样稿里的真实例子）不放进公开仓库，或改成虚构例子。
3. 第一次提交只包含扫描后的内容，不把扫描前的版本留在历史里。
4. GitHub 仓库由创始人的账号建立；推送前再确认一次。

## 异议与风险

- 被记录的人和团队也能看到判定规则，会有人专门找规则漏洞质疑结论。规则本该公开，这是代价。
- 工作记录（回头看、异议与风险、犯过的错）会公开。这符合透明，但创始人要接受。
- 公开提示词后，有人可能针对评审提示词写“诱导”内容放进将来的凭据里。凭据包已把来源内容当作数据处理，这一点要在评审提示词的审查中再看一次。

## 补充：网站上公开的结论和数据（创始人 2026-11-22 定）

网站上发布的条目、结论、说明和数据文件（包括 `index.json`）采用 **CC BY-NC-SA 4.0**：
可以引用、转载、研究使用，必须注明出自 KANVERIFY；不得用于商业目的；改编后的作品须用同样的许可。

- 目的：方法和代码公开，让更多人用同样的方法传播事实；但不让别人把我们花钱做出的成果直接拿去商用。
- 另外依靠欧盟对数据库的特别保护（法国适用）；具体效力需要律师确认，未核实。
- 要做的：网站页脚和方法页写明这一许可（交给设计和开发）；仓库 README 写明代码、文档、网站内容三种许可的区别。
