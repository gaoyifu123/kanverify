# 0001 技术选型：零依赖 Node.js、SQLite、静态 HTML

- 日期：2026-11-22
- 状态：已定（创始人 2026-11-21 在看板上回复“同意”）
- 谁定的：总协调提议，创始人确认

## 背景

一个人加 AI 搭建，两周上线。数据库必须只在创始人的电脑上，公开网站是它导出的只读副本。
这台电脑上已有 Node.js 26、Python 3.13 和 Git，没有别的数据库软件。

## 决定

- **语言和运行环境：** Node.js，用纯 JavaScript 模块，不加构建步骤。
- **数据库：** SQLite，用 Node.js 自带的 `node:sqlite`。整个数据库是一个文件。
- **依赖：** 目前为零。`package.json` 里没有任何第三方包。
- **测试：** Node.js 自带的测试运行器。
- **公开网站：** 由程序从数据库生成静态 HTML 文件，上传到静态托管。

## 依据哪条原则

- 原则 5（最简方案）：一个文件的数据库，不需要安装和维护数据库服务；备份就是复制一个文件。
- 原则 8（不受制于人）：没有第三方包，就没有会停止维护或改变许可的依赖。
- 原则 4（想清再写）：部件少，出问题时能看清是哪里。

## 放弃了什么

- **PostgreSQL。** 路线图早先列过。它需要单独安装和运行一个服务，现阶段的数据量
  （几百到几千条）用不上它的能力。
- **Next.js 等网站框架。** 网站是只读的静态页面，框架带来的大部分东西用不上。
- **TypeScript 的构建步骤。** 现在不加。Node.js 26 能直接运行带类型标注的文件，以后需要时再议。

## 什么情况下重新考虑

- 需要线上的读者提交或投票时：线上要有一个服务，届时再选。
- `node:sqlite` 出现无法绕过的缺陷时。
- 数据量大到单文件数据库明显变慢时。
