# 0004 用哪些设计类 skill

- 日期：2026-11-22
- 状态：已定（创始人 2026-11-21 在看板上回复“同意，可以安装”）。安装前先核实下面“没有核实的”三项。
- 谁定的：总协调提议，创始人确认

## 背景

创始人要求界面由口碑好的设计类 skill 和设计专长的 agent 主导，技术负责实现。
调研结果和每条说法的出处在 `docs/research/design-skills.md`。

## 提议

1. **`frontend-design`（Anthropic 官方）** 用来出设计稿。调研时它在官方市场显示
   一百多万次安装，带官方验证标记，只包含指导文字，不执行代码。
2. **Anthropic 的 `design` 插件** 用来做设计评审、无障碍检查和文案检查。
3. **自己写一份 `design/DESIGN.md`** 作为设计简报，钉住本项目的要求。这一条必须有，原因见下。

## 为什么第 3 条必须有

- `frontend-design` 倾向于做出“有个性”的设计。我们要的是平静、中立、可信，
  不给它明确的简报，它会往相反的方向走。
- 调研里没有任何一个 skill 覆盖法语和英语双语排版，也没有覆盖政治中立。
  这两点只能由我们自己写进简报。

## 没选的

- **Impeccable、UI UX Pro Max。** 星标很高，但会安装钩子、下载可执行文件或运行脚本。
  这是第三方代码在本机执行，和原则 8 相悖，收益不足以抵消。
- **Vercel 的 `web-design-guidelines`。** 只做代码审查，和 Anthropic 的 `design` 插件重叠。

## 2026-11-21 核实的结果

出处是 Claude Code 的官方文档和两个插件的代码仓库，由一个专门查文档的 agent 核实。

- **`frontend-design` 的安装**：市场名是 `claude-plugins-official`。命令行是
  `claude plugin install frontend-design@claude-plugins-official --scope project`；
  桌面应用里是点 + 号、Add plugins、选中后选 Install for this project。许可证 Apache-2.0。
- **这台电脑上没有命令行版的 Claude**，所以总协调装不了，由创始人在应用里装。应用里的入口没有亲自验证过。
- **`design` 插件**：许可证 Apache-2.0。但它附带一个连接配置文件，指向 Slack、Figma、Linear、Asana、
  Atlassian、Notion、Intercom 等外部服务，文档里没有找到单独关掉的办法。这是原先不知道的。
  **因此没有安装**，提议改为先不装，交创始人重新决定（看板事项 `design-plugin`）。
  这和本决定“不引入多余的外部依赖”的出发点一致。
- **子 agent 能自动读到项目的 CLAUDE.md**，所以原则文件会随它一起加载。

## 2026-11-22 的结果

创始人自己在应用里把两个插件都装上了。项目文件夹里没有新增设置文件，说明装在应用层面，不随项目走：
换一台电脑或换一个账号时要重新装。

`design` 插件附带的外部服务连接保持不配置、不使用。设计 agent 的职责文件里写明了这一点。
如果以后要接其中某一个服务，另行决定。

## 仍然没有核实的

- 设计 agent 的定义文件里引用插件里的 skill 时，名字要不要带插件前缀。文档只给了不带前缀的例子。
- `design` 插件的外部连接不配置时会不会报错。

## 依据哪条原则

- 原则 5（最简方案）：两个官方的加一份自己的简报，不叠更多。
- 原则 8（不受制于人）：不引入会在本机执行的第三方代码。
